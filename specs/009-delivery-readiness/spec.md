# Feature Specification: 售后闭环与可复现交付

**Feature Branch**: `phase5/delivery-readiness`
**Created**: 2026-10-14
**Status**: Draft
**Input**: 用户六项工作安排及《售后通_下一阶段开发安排_设计升级版 (1).pdf》。基于最新 main 继续推进，不上线、不创建云资源。

## User Scenarios & Testing

### User Story 1 - 可重复启动与恢复 (Priority: P1)

维护者按手册在本地启动完整系统，检查真实可用性，在重启或升级后继续处理原有服务事项。

**Why this priority**: 可交付不能依赖临时手工环境，也不能把进程存在当成业务就绪。
**Independent Test**: 在隔离的本地环境初始化、启动、重启、备份并恢复测试数据，核对消息、证据和办理记录。

**Acceptance Scenarios**:
1. **Given** 全新本地环境，**When** 按手册初始化并启动，**Then** 客户及客服入口可用，证据及消息在重启后保持一致。
2. **Given** 缺少模型或生产身份配置，**When** 检查运行状态，**Then** 明示不可用能力，不自动启用测试身份或虚构自动回复。
3. **Given** 数据库不可用或版本不匹配，**When** 检查就绪状态，**Then** 明确拒绝就绪且不泄露连接秘密。

### User Story 2 - 连续、受控的售后服务 (Priority: P1)

客户从咨询、关联 Case、补充证据到处理后核验，客服可以接管、审批并安排经客户同意的后续跟进。

**Why this priority**: 已有功能必须形成一条可验证的路径。
**Independent Test**: 使用客户与客服两种身份完成一次明确标识为模拟的服务流程，并执行拒绝、未知回执与未解决分支。

**Acceptance Scenarios**:
1. **Given** 一个已关联会话的未解决 Case，**When** 动作成功但客户尚未核验，**Then** 不允许标记解决；核验通过后才允许解决或关闭。
2. **Given** 图片尚未通过检查、审批拒绝或外部结果未知，**When** 用户继续操作，**Then** 展示真实等待或失败原因且不重复执行动作。
3. **Given** 服务完成，**When** 归档设备事实或安排跟进，**Then** 只归档已核验事实，跟进必须有客户同意，均可审计。

### User Story 3 - 界面及实时状态一致 (Priority: P1)

客户以聊天和当前任务为中心，客服集中处理会话、Case、设备、证据和审批；刷新及断网后仍可继续。

**Why this priority**: 状态一致性、错误恢复和权限隔离优先于视觉装饰。
**Independent Test**: 桌面及移动端使用真实数据，覆盖刷新、切换会话、断网、重复点击和人工接管。

**Acceptance Scenarios**:
1. **Given** 新消息、执行进度或卡片更新已保存，**When** 重连或刷新，**Then** 不丢失或重复展示，不混入其他会话数据。
2. **Given** 旧卡片或未知组件，**When** 用户操作，**Then** 拒绝过期写入并提供文本或固定表单出口。
3. **Given** 人工接管或客户身份，**When** 查看实时内容，**Then** 不出现越权的 Agent 回复、内部备注或原始推理。

### User Story 4 - Skill 可扩展且不越权 (Priority: P2)

维护者可识别每个 Skill 的用途、适用条件、版本、输入输出及执行记录，为情绪识别扩展提供清晰边界。

**Why this priority**: 情绪判断仅作为服务辅助，不得成为售后操作授权。
**Independent Test**: 验证 Skill 的发现、适用性、结构化结果和执行记录，拒绝未知版本、越权输入和无依据结果。

**Acceptance Scenarios**:
1. **Given** 情绪评估建议，**When** 记录类别、强度、置信度、依据和服务策略，**Then** 标记其推测属性，不自动退款、换货、关单或改变协作权限。
2. **Given** 尚未接入情绪识别模型，**When** 查询可用能力，**Then** 区分契约已准备与识别未启用，不显示虚假已执行结果。

### Edge Cases

- 数据库断开、迁移失败、重启时执行中的任务、过期租约与未知动作结果。
- 未授权、跨租户、无数据、上传不合法或检查失败、旧版本和幂等键冲突。
- 卡片不受支持、事件重复或乱序、历史补取分页、会话切换、网络恢复。
- 已关闭 Case 重开、未核验的事实归档、未同意的跟进、后台人工备注外泄。
- 缺少模型凭据、生产身份源、证书或对象存储时必须保留未验收状态。

## Requirements

### Functional Requirements

- **FR-001**: 提供隔离的开发、测试和生产运行配置及可重复启动步骤；生产配置禁止开发登录。
- **FR-002**: 提供独立后台任务进程、启动依赖、就绪检测与持久化证据存储。
- **FR-003**: 提供初始化、升级、重启、备份、恢复与回滚手册，危险清理必须显式确认且不能误删非演示数据。
- **FR-004**: 运行日志及错误报告不得包含秘密、完整聊天、原始推理或敏感证据；记录可关联的请求和耗时。
- **FR-005**: 保留并回归现有动作审批、执行、真实模拟回执、未知结果对账、客户核验、跟进及事实归档。
- **FR-006**: Case 解决须满足核验条件；动作成功、模型置信度及情绪判断不得替代核验。
- **FR-007**: 受控卡片由已授权状态生成；写操作再次验证角色、资源、状态、版本、输入和幂等性。
- **FR-008**: 实时内容可从持久历史恢复，去重并隔离会话和可见范围；仅展示真实执行摘要。
- **FR-009**: 客户界面突出聊天及当前任务；客服界面支持高效跨对象查看，提供完整错误、加载和移动端状态。
- **FR-010**: 定义 Skill 元数据、适用条件、发现选择、版本、结构化输入输出及执行审计边界。
- **FR-011**: 情绪结果包含类别、强度、置信度、不确定性、可追溯依据与限定服务策略，仅作辅助信号。
- **FR-012**: 建立售后 SOP、分层回归矩阵和本地演示步骤，记录成功及异常流程证据。
- **FR-013**: 采集首响应、首次真实进度、模型首内容、工具及操作耗时、错误率；缺失样本明确标为未测。
- **FR-014**: 分别报告真实模型、浏览器闭环、业务能力和部署准备验收，不能相互替代。

### Key Entities

- Conversation / Service Case / Device Passport：沿用独立对象及多对多关联，不将会话或整个 Case 复制成设备记忆。
- Agent Run / Service Task / Action：执行尝试、工作待办及受控业务操作，分别保留状态和回执。
- Skill Definition / Execution：方法契约、版本、适用性和有来源的运行记录，不等同于工具授权。
- Deployment Readiness：按组件分别记录健康、配置依赖及尚未关闭的验收门槛。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 完成至少一次从初始化到重启恢复的本地容器化演练，步骤可由手册复现。
- **SC-002**: 实测一条客户到客服、模拟动作、核验、后续跟进及事实归档的完整浏览器流程。
- **SC-003**: 每个关键异常场景有自动化回归或明确的手工验收证据；内部信息跨角色泄露为零。
- **SC-004**: 重复请求、刷新及重连测试中业务动作不重复执行、已保存消息不丢失。
- **SC-005**: 桌面和移动端均能完成核心任务，未知卡片及网络故障不阻断文本入口。
- **SC-006**: 性能报告分别给出样本数和 P50/P95，不以单次演示证明目标达成；未接入模型的指标明确未测。
- **SC-007**: 交付清晰的生产前置条件列表，不将本地模拟演练宣称为上线或真实模型验收。

## Assumptions

- 最新 main 已有图片、Mock 动作、客户核验、跟进和事实归档；先回归再修复，不重复建设。
- 本轮允许修改交付配置、CI、必要接口、前端及文档；不推送、不合并、不上线、不操作他人外部系统。
- 沿用现有本地账号；生产身份源及真实模型目的地需要另行配置授权，缺少时不假装通过。
- 使用现有设计参考与组件，优先改善业务路径，不更换技术栈。
- 对象存储及云网络配置在本地准备和验证，不创建实际云资源。
