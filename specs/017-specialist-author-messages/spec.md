# 诊断专家作者消息

## 状态

已实现并通过本地自动化验收。基于用户于 2026-10-17 确认的调研计划；Provider 质量与生产环境验收仍未执行。

## 目标

让经过验证的诊断结果在同一会话消息历史中以“诊断专家”为独立作者显示，同时由后端 Conversation Service 按当前权限决定消息是否公开。

## 范围

- `SPECIALIST` 作为服务端持久化消息作者类型，关联来源 `SpecialistRun`。
- 一次专家运行至多创建一条结果消息；消息与 `message.created` Outbox 原子提交。
- `AI_LEAD + AI_AUTO` 下符合条件的结果可成为 PUBLIC；其他有效策略下结果为 INTERNAL，仅客服可见。
- 诊断追问继续使用问题卡；安全停止、人工复核不公开专家自由文本。
- 普通消息写入接口不能指定专家作者、展示名称或运行来源。
- 前端从消息历史和现有消息刷新机制显示固定“诊断专家”作者和“AI 假设（待核验）”标记。

## 非目标

- 诊断 Agent 获取登录身份或直接访问聊天/消息 API。
- 公开内部摘要、工具调用、原始模型推理、私密信息或未经审查的引用原文。
- 绕过客服审核，或将专家消息自动转换成公开回复审批草稿。
- 取代 Service Agent 的协调职责、改变 Case/DeviceFact 的验证状态或扩展真实 Anker API。

## 用户场景与验收

1. 在 ACTIVE 且 `AI_LEAD + AI_AUTO` 会话中，诊断运行完成且无需追问/安全处置/人工复核时，客户和客服都能从历史看到一条作者为“诊断专家”的待核验结果。
2. 在 `CO_SERVICE`、`AI_REVIEW_REQUIRED` 或 `HUMAN_LEAD` 策略下，客服能看到 INTERNAL 专家结果，客户消息历史和事件流均不可见。
3. 追问继续通过现有问题卡；安全停止/人工复核保留现有安全回复，不向客户公开专家自由文本。
4. 重试相同 SpecialistRun 不重复创建消息；不同租户、不同会话、失效会话或失效 AgentRun lease 不能写入专家消息。
5. 客户调用普通消息 API 无法伪造 SPECIALIST 或 SpecialistRun 来源。
6. 主 Agent 保留协调者回复职责，并收到“不要复述已发布专家结论”的结果状态；客服快捷回复仅绑定 AGENT 消息。

## 安全正文投影

公开正文仅由服务端从 `DiagnosticResult.assessment` 和安全的下一步信息投影，带“初步假设（待核验）”标识。使用现有安全文本检查并为不合格文本降级到固定说明；不使用 `staff_summary`、模型推理、工具数据或来源原文。SAFETY_STOP/HUMAN_REVIEW 走现有固定回复。未经当前 PUBLIC policy 授权时绝不把 INTERNAL 消息提升为 PUBLIC。
