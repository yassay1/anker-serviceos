# Quickstart: 高级动态服务界面\n\nThis is a planned validation guide. It does not imply the feature is implemented yet.\n\n## Preconditions\n\n1. Use an isolated local PostgreSQL 17 + pgvector development/test database, never production.\n2. Apply current backend migrations and initialize local development identities using the commands in the repository [README](../../README.md#本地启动).\n3. Start the API and frontend as documented in [backend README](../../backend/README.md) and [frontend README](../../frontend/README.md).\n4. A live language-model provider is optional for deterministic projection/render checks. Real provider selection evaluation requires an explicitly approved provider configuration and must be reported separately.\n\n## Planned scenarios\n\n1. **Safe model proposal**: Submit a customer question whose authorized context requires clarification. Confirm the projection publishes a supported choice/question card, that labels/options are clear, and that submitting a choice reaches the existing conversation/diagnostic application path.\n2. **Risk-first guidance**: Use an approved hazardous-symptom fixture. Confirm a safety notice appears before general steps, includes a stop condition, and is not generated solely from unsupported text or a UI hint.\n3. **Evidence collection**: Create a Case with a missing evidence item. Confirm the customer sees the requested evidence and current upload/check state; an uninspected upload is not labeled clean or analyzed.\n4. **Service progress**: Vary actual Case, Task, Mock Action, and Verification states. Confirm display follows durable records and does not mark a Case resolved from a successful Mock receipt alone.\n5. **Staff isolation**: Read the same conversation as customer and staff. Confirm internal summaries and flow nodes are only returned/rendered for authorized staff; cross-tenant or unlinked resources are rejected.\n6. **Unsupported/stale fallback**: Submit unknown component, invalid source, expired document, old resource version, malformed payload, and disabled-provider cases. Confirm ordinary text service remains available and no stale write is replayed.\n7. **Responsive/accessibility**: Verify keyboard-only operation, screen-reader labels, error and submission feedback, chart text equivalent, and 390px/desktop layouts.\n\n## Planned commands after implementation\n\nFrom the repository root, use the actual commands listed in [README validation](../../README.md#校验与契约生成), plus the targeted backend and browser scenarios added by the feature tasks. Use an isolated disposable Postgres test URL for PostgreSQL-backed suites. Do not treat controlled HTTP fixtures as proof of backend authorization, real provider quality, or external Anker integration.\n\nExpected outcome: all supported surfaces pass role/source/version and fallback checks; all business actions use actual typed application services; unresolved provider and production source approval gates remain explicitly reported.\n
