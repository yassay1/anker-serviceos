# Feature Specification: Desk Case Summary

## User Scenarios & Testing

### User Story 1 - 查看有来源的案例摘要 (P1)

客服打开会话时看到所有关联 Case 的问题、状态、版本、设备身份及证据，逐项知道陈述来源和核验状态，无需客户重述。一个会话可以关联多个 Case，一个 Case 也可以跨会话。

**Acceptance**: 同租户客服可读；无关联 Case 显示空状态；候选和模型假设绝不显示为已核验；客户与跨租户身份不得读取客服摘要。

## Requirements

- **FR-001**: 摘要必须以授权的 Conversation 为入口，仅投影已关联 Case。
- **FR-002**: 问题、证据、设备身份与设备事实都必须显示来源与核验状态；未经核验内容不得升级表述。
- **FR-003**: 客服页面必须展示多 Case 与无 Case 状态，并明确版本与等待状态。
- **FR-004**: 客户和其他租户无法读取此摘要。

## Success Criteria

- **SC-001**: 客服一次打开会话即可看见全部关联 Case 和每项事实的来源与状态。
- **SC-002**: 权限拒绝、候选事实和无 Case 场景全部有可重复的验收结果。

## Assumptions

本切片只读现有持久数据；证据创建、外部动作和结果核验不在此切片。问题原文标记为客户或客服创建时的陈述，不作为已核验设备事实。
