# 独立 UI 评审原型

优先打开 [`mobile-first-review.html`](mobile-first-review.html) 评审客户与客服的手机优先闭环：客户首屏突出「进入对话」并列出历史对话和服务记录入口；工作区在品牌栏下切换对话、处理详情和关联设备，另设新对话与唯一的联系人工操作。客服端从处理队列进入客户会话和服务资料。打开 `index.html` 可查看较早的客户服务会话与客服工作台结构；[`customer-service-flow.html`](customer-service-flow.html) 和 [`visual-exploration.html`](visual-exploration.html) 保留为较早的客户视觉探索稿。

双端评审稿在 1100px 以下使用单列面板切换；客服选中任务后通过“处理队列 / 客户会话 / 服务资料”切换。客户对话下方显示助手与专项诊断的参与状态，并提供可点击的「人工」入口。客服时间线只放客户消息与已发送的公开回复；AI 建议另列为「未发送 · 仅客服可见」，放入编辑器不会自动发送。客服编辑器持续标注客户可见。桌面保留队列、会话与服务资料并列。页面仅呈现设计示意，不调用接口或提交业务操作。

## 客户连续体验

主评审稿入口页以唯一的「进入对话」按钮为首屏视觉焦点；点击后展示同一对话工作区。工作区提供「对话 / 处理详情 / 关联设备」三个视图入口；首页分别进入 Conversation 历史和 Service Case 服务记录；「新对话」与对话底部的人工协助按钮作为操作。客户服务栏中前两项是状态：「售后助手 正在分析」「专项诊断 已参与」；「人工」是可点击按钮，不是第三个在线状态灯。客服仍从工作队列开始，客服工作视图不复用客户操作。

人工按钮在服务工作区只有一个入口；原型不会提交消息、创建会话/Case/客服任务、上传证据或改变业务阶段。团队灯号是静态视觉示例，不模拟真实在线；真实实现须使用当前轮次、PUBLIC 可见的持久活动事件。等待只显示服务阶段，不显示未经接口支持的预计时长。满意度回执尚无评价 API，因此不展示提交操作。本轮仅在现有约 1260×708 浏览器视口进行界面检查；360/375/390 手机和平板断点仍待进一步复核。

客服原型的消息时间线不包含 AI 草稿。AI 建议卡关联最新客户消息并标记未发送；「放入回复框」只更新编辑器。新客户消息到达后，旧建议须标为过期或要求重新核对。发送动作仍是示意，不调用后端。

## 视觉方向探索

| 方向 | 版式重心 | 适合的体验 |
|---|---|---|
| A · 品牌欢迎式 | 大留白欢迎区、原创设备矢量图、历史记录与当前对话并列，下一步单独突出 | 品牌感更强，进入服务更从容 |
| B · 精密服务工作区 | 服务标题与主操作置顶，记录列表、对话、阶段/设备资料三栏协作 | 更快定位当前问题和下一步，适合连续处理 |

两版参考了图片中的明亮表面、深蓝标题、品牌蓝主操作、桌面分区和阶段提示；不复用参考图的人物、设备型号、案例、时间或消息。案例均为虚构的蓝牙音箱配对问题。

原型纯静态、无依赖，不读取现有前端代码、不连接 API，也不提交消息、图片、人工任务、审批或案例状态。连续体验原型中的页面切换只改变本地展示状态；其他不可执行操作会提示当前是设计示意。

页面中的人名、问题、设备、消息、时间和状态都是虚构的布局示例。它们只用于讨论视觉方向和信息层级，不能作为功能已实现或服务记录真实存在的证据。

## 评审重点

- 首页到新服务、继续已有服务、返回入口的路径是否自然。
- 客户首屏的单一「进入对话」按钮是否足够清楚；进入后 Conversation 历史与 Case 服务记录是否分得开。
- 「新对话」和「联系人工客服」是否像当前上下文中的操作，而不是内容导航；人工协助是否仍只有一个入口。
- 客户端团队参与点是否能看出服务角色与当前阶段，是否能明确分辨「人工」是可点击入口而非在线灯号。
- 服务对话区是否仍是主视觉，三栏在桌面和小屏上的切换是否清楚。
- A 与 B 哪些视觉特征值得保留在组合后的客户页面。
- 设备插画、欢迎区、服务阶段和主操作的权重是否平衡。
- 对话宽度、历史记录密度和证据补充卡是否易读。
- 窄屏下服务记录、当前对话和服务详情的切换是否清楚。
- 客服原型中队列/对话/案例资料、公开回复、AI 草稿和服务阶段是否容易区分。
- 双端手机模式下角色切换、客服队列到会话/服务资料的路径是否自然；公开回复与 AI 草稿是否一眼可辨，服务阶段是否始终清楚。
- 客服消息时间线是否只包含已发生的公开消息；AI 建议的来源、未发送状态与“插入不等于发送”是否一眼可辨。
- 客服是否优先看到该处理的任务，并能从队列进入客户消息与服务资料；操作没有照搬客户页的历史/新对话入口。
- 以 360×800、375×812、390×844 检查触控、单列阅读、长消息和固定输入区；以 768×1024 检查平板切换，以 1280×800 检查桌面并列布局。

本原型不代表最终页面规格。评审决定应回填到 `../visual-system.md` 和 `../page-specs.md` 后再进入应用实现。
