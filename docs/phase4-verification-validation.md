# 阶段 4 结果核验增量验收

用户确认：第一种动作仅模拟提交服务请求；另一名主管或管理员审批且不能自批；解决必须同时具备成功 Mock 回执与客户本人明确确认。代码将这两项解决条件按动作冻结为 Resolution Contract。客户可提交 `WORKING`、`NOT_WORKING`、`UNCERTAIN`，后端在同一事务内核对 Case/Contract 版本、租户、所有权、最新动作回执、可见证据、幂等编号，并保存观察、Case 状态和公开事件。客服只读，不能替客户确认。

本地验收（2026-10-14）：PostgreSQL 后端完整回归 100 通过；迁移升级到 `0011_resolution_verification` 后 `alembic check` 无漂移；OpenAPI 与拟定契约检查、前端 API 同步、类型检查和构建通过；前端浏览器回归 33 通过，真实 API 浏览器回归 4 通过。真实流程中从动作申请、主管审批、Worker 成功 Mock 回执到客户确认，Case 由服务端进入 `RESOLVED`；移动端页面已查看。远端 CI 状态以对应 PR 为准。

范围限制：此核验仅用于开发/测试环境的 Mock 服务请求。它不证明真实维修、退款、保修或设备身份；后续跟进和 Device 可信事实归档仍待实施。图片限制、多模态理解及生产对象存储仍待后续阶段。

迁移会为已有模拟动作补冻结条件，不会自动改写历史 Case 状态。若旧开发数据曾在核验保护上线前把有动作的 Case 标为 `RESOLVED`，需人工审阅该历史记录；不能把补入的 Contract 当作已有客户确认。
