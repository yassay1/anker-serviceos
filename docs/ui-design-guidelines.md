# Web 界面设计指南（参考图转译草案）

本指南把[两组 Web 参考图](design-references/README.md)转成可评审的视觉和交互方向，重点是[2026-10-17 客户服务界面参考图](design-references/2026-10-17-customer/README.md)。图片是效果参考；当前实现与能力边界以代码、真实 API 和[开发计划](development-plan.md)为准。

## 整体方向

- 客户侧：暖色、明亮、低密度，突出“提出问题、理解下一步、查看真实进度”。
- 客服侧：同一品牌语言下提高信息密度，突出“选择案例、查看证据、决定下一动作”。
- 两侧共用排版、颜色语义、按钮和状态组件；在一个 Web 应用里按角色提供不同视图。

建议先在 CSS 变量中试用下列色板，再通过浏览器截图和对比度检查调整：

| 语义 | 建议起点 | 用途 |
|---|---|---|
| 深色文字 | `#14243D` | 标题、主要数据 |
| 品牌蓝 | `#3267F4` | 主要按钮、当前选中项 |
| 暖色画布 | `#F7F5F2` | 客户侧页面背景 |
| 卡片表面 | `#FFFFFF` | 内容区、输入区 |
| 柔和描边 | `#E2E7EF` | 卡片与表单边界 |
| 次要文字 | `#5F6F83` | 辅助说明 |
| 暖色点缀 | `#FFEBDD` | 引导、人工服务提示 |

成功、警告、危险和等待状态要同时有文字标签，不只靠颜色区分。正文从 16px 与约 1.5 行高起步；桌面使用清晰的区域分栏，窄屏将次要信息收起或下移，保留消息输入和当前任务。

## 页面与实现顺序

| 参考图 | 应先提取的结构 | 依赖真实业务能力的部分 |
|---|---|---|
| 客户首页 | 品牌导航、问题入口、服务/设备区的视觉层级 | 搜索、设备卡、统计和服务进度 |
| AI 诊断 | 会话区、问题卡、输入区、辅助侧栏 | 图片上传、动态卡、模型进度 |
| 客户服务详情 | Case 信息、真实事件时间线、下一步提示 | 附件、维修安排、结果核验 |
| 客服工作台 | 左侧导航、列表、筛选区、工作区密度 | 指标、AI 解决率、自动分流 |
| 客服案例详情 | 会话、Case 摘要、证据与操作区 | 诊断结论、审批、外部动作 |

先统一导航、容器、卡片、按钮、表单、消息与状态标签，再在现有 `/support`、`/desk` 上应用。新增页面和可执行按钮先核对[当前 OpenAPI](../contracts/openapi.json)、角色权限、版本与幂等规则；不能用静态演示数据模拟成功业务状态。

## 客户会话桌面优先对齐

本节是对 2026-10-17 用户参考图的转译，也是当前代码的核对入口，不替代阶段验收记录。

### 桌面结构

- 在宽屏客户 `/support` 中并排呈现会话历史、当前对话和服务资料，避免把历史记录压进遮挡聊天内容的浮层。
- 页面级标题为“对话”，副标题说明可继续已有服务或开始新问题；“开始新对话”是此区域唯一主操作。
- 会话列表负责搜索、切换与显示真实 Case 状态；聊天区负责消息、必要的客户行动和输入；资料区负责真实关联服务信息与唯一的真人协助入口。
- 使用 `minmax(0, 1fr)` 和局部滚动约束长列表，确保宽度收缩时消息正文仍有可读空间。平板/手机保留显式的列表、对话、资料切换并维持草稿。

### 客户可见内容

- 展示已保存的客户/客服消息、安全提醒、仍需要客户补充的信息、证据上传和有业务含义的真实等待状态。
- 不将 Agent/Worker 的 `RUNNING`、检索、`COMPLETED` 或审批生命周期渲染成聊天卡片；它们不是客户服务结果。客服内部仍可通过授权工作区查看真实运行信息。
- 真人协助保持一个入口。会话中的证据/诊断交互仍放在消息上下文；协助入口放在资料区，提交继续调用已有 UI action 和后端授权、幂等、未知结果恢复。
- “已解决”只能由真实结果核验判定。截图中的诊断、设备型号、时间、进度、承诺和示例姓名不能进入生产展示数据。

### 当前实现范围

`/support` 已采用桌面三栏会话工作区，宽屏默认显示历史列表；创建会话后列表仍保持可见。客户聊天过滤纯 Agent 运行生命周期卡片，保留安全与客户待办信息。协助在资料区只有一个入口，并复用当前授权动作。窄屏继续使用面板切换。

本轮涉及文件、实际验证命令、结果与限制记录见[客户页面对齐验收记录](customer-ui-alignment-validation.md)。正式完成状态仍以[开发计划](development-plan.md)及对应阶段验收记录为准。

## 交互验收

每个实际功能都检查加载、空态、成功、失败、无权限、过期版本和断线恢复。消息发送保留服务器回执与原幂等键重试；事件与任务进度只从已持久化事实展示。客户看不到内部备注、Agent 草稿或无权访问的 Case/Device 信息。键盘焦点、可见标签、足够对比度、移动端无横向溢出和文本降级与视觉效果一起验收。

图片内的样例设备、品牌标识、用户头像、案例编号、百分比、维修时效和 AI 判断均为构图素材。产品文案、图标与设备素材需另行确认来源和真实性。
